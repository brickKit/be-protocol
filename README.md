# be-protocol

组件协议：任何语言写的组件都必须遵守的规则（线上格式、表结构、配置键这一层），以及跨语言必须得到相同结果的语义向量。官方 SDK（Go、Python、TypeScript）是它的参考实现，一致性套件从外部按它检验运行中的组件（装配项目的协议 18）。

旧版本（1.0.0 的预发布 rc.1、rc.2）在分支 `legacy/v1`，标签保留；本主分支按终局设计从零开始（D59），版本从 `3.0.0` 起（A110）。规则的设计依据在装配项目 [be-assembly-standard](https://github.com/brickKit/be-assembly-standard) 的正式文档（`docs/zh/`）；某条规则写进本仓库之后，规则正文只在这里（A99）。

## 内容

| 目录 | 是什么 |
| --- | --- |
| `spec/` | 规范，按章编号；每条规则有编号（`P<章>.<序号>`）与层级（必须、应当、内部），见 [阅读说明](spec/00-reading.md) |
| `vectors/` | 语义向量：JSON，一个文件一个主题；`SHA256SUMS` 记录每个文件的摘要 |
| `schemas/` | JSON Schema（错误体等） |
| `migrations/` | SDK 自己的表与函数（单号序列、发件表与纪元、工作项、审计、投影、按月分区）的迁移文件：三种语言的 SDK 执行同一份（第 5 章 P5.12） |
| `data/` | 共享数据：`pinyin.tsv`（搜索列用的每字首选读音，第 9 章 P9.6；来源与许可见 `PINYIN-LICENSE`） |
| `migrations-bus/` | PostgreSQL 队列运输的表，建在总线库自己的 schema（第 6 章 P6.23） |

本模块同时是一个 Go 模块（`github.com/brickKit/be-protocol/v3`），用 `embed` 交出 `vectors/`、`schemas/`、`migrations/`、`migrations-bus/` 与 `data/`。SDK 按精确版本引用它，在 L1 测试中逐条运行向量；其他语言按同一版本的标签读取这些目录。

## 当前范围

代表部署实验（装配项目的实验计划第 2 步）写到第 9 章：生命周期与健康、配置、错误、组件之间的调用、数据库与按月分区、事件与运输、后台工作项、身份授权与审计的组件一侧、列表搜索与投影。各章开头写明哪些部分随后续任务加入；其余规则在重建时按装配项目的 `be-protocol` 承接清单逐条重审写入。

## 版本

语义版本。开发中发预发布 `3.0.0-alpha.N`；同一主版本内只追加规则与字段，收紧必须规则或改变含义发新主版本（协议 18）。向量只随协议版本变化；某个 SDK 与向量不符是该 SDK 的缺陷，不改向量迁就实现。

## 检查

`make check`：校验每个向量文件的结构与 `SHA256SUMS`，并用测试代码里的参考计算核对向量的期望值是否自洽（这些参考计算只用于发现向量本身的笔误，不是 SDK）。需要 Go 1.26。
