# 05 数据库与数据形态

依据：装配项目协议 14 的“数据库”“记录身份与唯一性”“单号”“时间、日历与期间”“金额、数量、汇率与单位”“结构迁移与版本兼容”“参数起始值”；协议 17 的“外壳义务”“预算”。本章写连接、事务、迁移、身份、单号、按月分区、金额与业务日期；列表游标见 [09](09-lists-search-projections.md)。汇率、单位换算与税额随用到它们的组件加入。连接键见 [02](02-configuration.md#共享连接键)。

## 连接池

| 编号 | 层级 | 规则 | 检验 |
| --- | --- | --- | --- |
| P5.1 | 必须 | 单独运行时，组件以运行角色（`PG_USER`）登录，用自己的一个池。外壳中，同一数据库目标（`PG_HOST`、`PG_PORT`、`PG_DATABASE` 相同）的成员共用外壳的一个池，以外壳登录角色（`PG_SHELL_USER`）登录；不同目标各一个池。外壳登录角色以 `WITH INHERIT FALSE, SET TRUE` 获授成员的运行角色，从不获授属主角色；授予由装配的建库脚本完成 | CK-DB-01 |
| P5.2 | 必须 | 池的大小 = 用这个池的全部成员的前台与后台预算之和（`PG_POOL_FOREGROUND` + `PG_POOL_BACKGROUND`）。每个成员同时持有的连接不超过自己的预算：前台事务等预算最多 2 秒，等不到答 `SERVICE_BUSY`（元数据 `resource=db_pool`，`Retry-After: 1`）；后台事务一直等到取消 | CK-DB-02 |
| P5.3 | 必须 | `PG_POOLER_PREPARED=false` 时不使用协议层的预编译语句（Go 的 pgx 用 `CacheDescribe`，其他语言用各自驱动的等价方式）；同一目标的成员这个值不同时外壳不启动（P2.11） | CK-SH-02 |
| P5.4 | 内部 | 外壳共享池里，不同成员的同一段 SQL 不共用缓存的语句（官方 SDK 在每条语句前加成员的注释前缀 `/* <组件 ID> */ `）；否则表结构不同的成员会得到“缓存的计划改变了结果类型” | SDK 测试 |

## 事务入口

| 编号 | 层级 | 规则 | 检验 |
| --- | --- | --- | --- |
| P5.5 | 必须 | 模块只经运行时的事务入口访问数据库。每个事务开始时在事务内设置：角色（成员的运行角色）、`search_path`（成员的 schema）、`statement_timeout`、`lock_timeout`、`idle_in_transaction_session_timeout`、`application_name`（成员的组件 ID）；全部用事务级设置（`SET LOCAL` 或 `set_config(…, true)`），事务结束后连接上不留下任何设置 | CK-DB-03 |
| P5.30 | 应当 | 运行时的事务入口拒绝会把状态留在池中连接上的语句，报错而不执行：不带 `LOCAL` 的 `SET`（`SET TRANSACTION`、`SET CONSTRAINTS` 只作用于本事务，除外）、`RESET`、`DISCARD`、`LISTEN`、`UNLISTEN`、会话级的咨询锁（`pg_advisory_lock`、`pg_try_advisory_lock` 及其共享版本；事务级的 `pg_advisory_xact_lock` 允许）。违规在写错的那一刻暴露，不靠连接归还时的会话重置悄悄清掉；也因此连接归还连接池时不做会话重置。Python 的 asyncpg 默认在每次归还时执行一组重置语句，短事务每个多一次往返，实测占 PostgreSQL 每个短事务约 27% 的 CPU | SDK 测试 |
| P5.31 | 应当 | P5.30 之外，两道补充让池中连接不带会话状态：① 迁移检查拒绝函数、过程与 `DO` 块正文里的会话状态（规则 `SESSION_IN_BODY`：不带 `LOCAL` 的 `SET`、`RESET`、`set_config(…, false)`、会话级咨询锁；动态 `EXECUTE` 的字符串不检查），运行时的事务入口对 `DO` 块做同样的检查。② 事务结束、连接归还连接池之前，SDK 比较服务端推送的参数（`TimeZone`、`DateStyle`、`IntervalStyle`、`client_encoding`、`standard_conforming_strings`、`application_name`）与建连时的值，不同就关闭这条连接、不放回池，并记一条错误日志（成员、参数、两个值）。不需要额外往返：这些参数在变化时由服务端主动推送，函数里改的也一样。角色、`search_path` 与各项超时由每个事务开始时的事务内设置覆盖（P5.5），不在此列；服务端不推送、只影响性能的设置（如 `work_mem`）不检查 | 向量 `migration-lint`、SDK 测试 |
| P5.6 | 必须 | 超时取成员的配置，缺省：语句 5 秒（`PG_STATEMENT_TIMEOUT`）、锁等待 2 秒（`PG_LOCK_TIMEOUT`）、事务内空闲 10 秒（`PG_IDLE_IN_TX_TIMEOUT`）。超时从不按角色设置（`SET ROLE` 之后 PostgreSQL 不应用角色级设置）；单个事务可以声明更长的语句超时（报表、后台） | CK-DB-03 |
| P5.7 | 必须 | 隔离级别缺省读已提交，事务可以声明可串行化。只有 SQLSTATE `40001` 与 `40P01` 重试，重做整个事务，每个事务最多 3 次尝试；其他错误不重试 | 向量 `db-errors` |
| P5.8 | 必须 | 数据库错误按向量 `db-errors` 映射成原因（[03](03-errors.md)）；模块自己返回的错误原样传出 | 向量 `db-errors` |
| P5.9 | 内部 | 事务内不再开事务（答 `INTERNAL`，日志写 `NESTED_TX`）；事务内不发网络调用（出站客户端拒绝，答 `INTERNAL`，日志写 `NETWORK_IN_TX`，随 [04](04-calls.md) 的客户端实现） | SDK 测试 |

## 启动

| 编号 | 层级 | 规则 | 检验 |
| --- | --- | --- | --- |
| P5.10 | 必须 | 启动时连不上数据库（连接被拒、超时）不退出：保持“启动中”并每秒重试，直到连上或收到停止信号（此时退出码 0）。数据库拒绝凭据时以 78 退出；库不存在、`fsync` 不是 `on`、`synchronous_commit` 弱于 `on`（只接受 `on`、`remote_write`、`remote_apply`）时以 69 退出 | CK-DB-04 |

## 迁移入口

| 编号 | 层级 | 规则 | 检验 |
| --- | --- | --- | --- |
| P5.11 | 必须 | `migrate` 入口以属主角色（`PG_OWNER_USER`）直连数据库（`PG_MIGRATION_HOST`、`PG_MIGRATION_PORT`，未设置时用 `PG_HOST`、`PG_PORT`），连接上 `search_path` 为组件的 schema、`lock_timeout` 3 秒。缺少属主凭据时以 78 退出。`serve` 不解析也不使用属主凭据 | CK-LC-02 |
| P5.12 | 必须 | 先执行 SDK 自己的迁移（本仓库 `migrations/` 下的文件，状态表 `be_sdk_migrations`），再执行组件的迁移（状态表 `schema_migrations`）；两张状态表都在组件的 schema 里，形状为 `(version bigint primary key, dirty boolean not null)`，与 golang-migrate 相同，所以三种语言的 SDK 读写同一份状态 | CK-DB-05、CK-DB-09 |
| P5.13 | 必须 | 迁移文件名为 `<版本>_<小写下划线标题>.up.sql`，版本是十进制整数，按数值顺序执行；每个文件作为一个事务执行。执行前检查全部文件，不合格时一个也不执行，按向量 `migration-lint` 的规则编号逐条报出 | 向量 `migration-lint` |
| P5.14 | 必须 | 等锁超时（`55P03`）的那次尝试回滚后重试，最多 5 次；最后一次仍超时时失败，报告阻塞者（进程号、用户、应用名；能看到时加状态、事务时长与语句）。属主角色看不到其他角色会话的语句与状态（需要 `pg_read_all_stats`，不授予），所以只保证进程号、用户与应用名 | CK-DB-06 |
| P5.15 | 必须 | 本次执行中失败的文件（它的事务已回滚）在迁移锁内把状态退回上一个版本，所以修好后可以直接再跑。开始时发现状态被标记为 dirty（上一次执行在文件中途被中断），不自动处理：失败并写明版本与文件，由人核对后修正状态表 | CK-DB-05 |
| P5.16 | 必须 | 两个实例同时执行迁移时都成功，每个文件只执行一次（迁移锁是按库、schema 与状态表计算的咨询锁，等待它同样受 `lock_timeout` 约束） | CK-DB-05 |

## 记录身份与单号

| 编号 | 层级 | 规则 | 检验 |
| --- | --- | --- | --- |
| P5.17 | 必须 | 记录身份是 UUIDv7（RFC 9562），由组件经 SDK 在插入前生成；同一进程内按生成顺序递增 | SDK 测试 |
| P5.18 | 必须 | 单号序列存在 SDK 的表 `be_doc_series`（`migrations/0001_doc_series.up.sql`）里，每个序列一行，键为 `<法人>/<序列代码>/<期间>`（期间为空表示不重新开始） | CK-DB-07 |
| P5.19 | 必须 | 连续序列在签发的事务中取号：插入或把该行的 `last_number` 加一并返回，行锁持有到事务结束；事务回滚则号也回滚，不留缺号。允许缺号的序列在自己的短事务中取号。同一序列先后以不同的连续性使用时答 `INTERNAL`（事务回滚） | CK-DB-07 |
| P5.20 | 必须 | 导入的历史单号登记为序列的已用最大值（只增不减），新号从它之后开始 | CK-DB-07 |

## 分区

| 编号 | 层级 | 规则 | 检验 |
| --- | --- | --- | --- |
| P5.21 | 必须 | 分区表按一个显式的分区键列（`date` 或 `timestamptz`，业务日期、期间或创建时刻，不从身份推出）做范围分区；按身份去重的表（收件表、幂等记录、身份登记表、消费进度）不分区。按月分区的表在组件自己的迁移中建立后，用 SDK 迁移提供的 `be_declare_monthly_partitions('<表>', <预建月数>)`（1–24，缺省 3）声明，声明时校验表的形状（表名不超过 55 字节，分区名才不会被截断）、写入声明表 `be_partition_plan` 并建好当月起的分区；删除或改名已声明的表的迁移同时调用 `be_undeclare_monthly_partitions('<表>')`，否则维护报错 | CK-DB-08 |
| CK-DB-09 | 迁移之后从外部看：两张状态表与 SDK 的表都在组件 schema、形状正确；schema 中的对象都属于属主角色；运行角色能使用 schema 与增删改查表，不能在 schema 中建对象；属主建的函数不对 `PUBLIC` 开放执行；两种角色在 `public` 中没有对象 |
| P5.22 | 必须 | 运行期的预建由 SDK 迁移提供的 `be_maintain_partitions()` 执行：以属主身份运行（`SECURITY DEFINER`，`search_path` 固定为组件 schema 与 `pg_temp`，时区 UTC），为每张声明的表补齐当月到当月加预建月数的分区，名为 `<表>_p<YYYYMM>`、边界为 [月初, 下月初)；先建空表再 `ATTACH PARTITION`；同一 schema 内用事务级咨询锁串行；不做其他任何 DDL。声明表只有属主能写（触发器拒绝其他角色） | CK-DB-08 |
| P5.23 | 必须 | 函数的执行权由建库与授权脚本授予，迁移不含授权语句：属主建的函数默认不对 `PUBLIC` 开放执行（`ALTER DEFAULT PRIVILEGES FOR ROLE <属主> REVOKE EXECUTE ON FUNCTIONS FROM PUBLIC`），只授予本组件的运行角色（`… IN SCHEMA <schema> GRANT EXECUTE ON FUNCTIONS TO <运行角色>`） | CK-DB-08、CK-DB-09 |
| P5.24 | 必须 | 每个有数据库的成员带一个 SDK 自带的 singleton 作业 `be.partitions.maintain`（每小时一次，副作用 `local`）调用维护函数。同名分区的边界不符、已摘除，或新分区与已有分区重叠时，维护失败并告警（作业按失败处理），不跳过、不改动已有分区 | CK-DB-08 |

## 金额与业务日期

| 编号 | 层级 | 规则 | 检验 |
| --- | --- | --- | --- |
| P5.25 | 必须 | 金额、单价、数量与汇率在契约中是十进制字符串：`-?` 整数部分（无前导零）`[.小数部分]`，最多 38 位数字；不接受指数、正号、空格、非 ASCII 数字与 `-0`。金额按币种的小数位解析：小数位多于币种的（多出的不全是 0）不合格，答 `REQUEST_INVALID`，不静默舍入。输出按币种的小数位格式化（`12.30`），零不带负号；规范编码去掉末尾零（P8.8），两种文本形式不能互换。内存中用十进制类型，任何环节不经过浮点 | 向量 `money` |
| P5.26 | 必须 | 舍入只在 SDK 中进行：按币种的最小单位（小数位）与声明的方式，缺省四舍五入远离零（`half_away_from_zero`），可选银行家舍入（`half_even`） | 向量 `money` |
| P5.27 | 必须 | 现金舍入：先按声明的方式舍入到现金单位（例如 0.05）的整数倍，再按币种小数位格式化 | 向量 `money` |
| P5.28 | 必须 | 分摊用最大余数法：总额按权重（非负、和大于零）分成若干份，每份是最小单位的整数倍；余下的最小单位依次给余数最大的份，余数相同给前面的；负数按绝对值分摊后取负；各份之和恰好等于总额。每行独立舍入会产生尾差，不允许 | 向量 `money` |
| P5.29 | 必须 | 业务日期是时刻在法人 IANA 时区中的本地日期；“今天”由 SDK 按法人记录上的时区计算后作为参数传入，SQL 不向数据库询问当前日期（会话时区固定为 UTC） | 向量 `business-date` |

## 检查编号

| 编号 | 检查 |
| --- | --- |
| CK-DB-01 | 外壳中两个成员同一目标：数据库里只有外壳登录角色的连接；外壳登录角色在事务外读不到任何成员的表 |
| CK-DB-02 | 前台预算为 1 时，第二个并发事务在 2 秒左右答 `SERVICE_BUSY`，带 `resource=db_pool` |
| CK-DB-03 | 事务内看到成员的角色、schema 与超时；事务结束后同一连接回到登录角色、缺省 `search_path` 与零超时 |
| CK-DB-04 | 凭据错误退出码 78；库不存在 69；`synchronous_commit=off` 的库 69；数据库晚于组件启动时组件等到它 |
| CK-DB-05 | 连续执行两次都成功；状态表只在组件 schema；中途失败的文件不留痕迹，修好后再跑成功；两个实例同时执行都成功 |
| CK-DB-06 | 另一个会话持有表锁时，迁移在 5 次 × 3 秒后失败，报告中有阻塞者的进程号与应用名 |
| CK-DB-07 | 连续序列回滚不留缺号、并发不重号；允许缺号的序列从导入的最大值之后继续；连续性用错时失败 |
| CK-DB-08 | 声明后当月起的分区存在且行能写入；重复维护不重复建；运行角色能执行维护、不能写声明表；别的组件的运行角色不能执行；临时表冒充声明表无效；边界不符或重叠时维护失败 |
