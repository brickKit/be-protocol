# 11 边缘的会话层

依据：装配项目协议 20 的登录与会话、底层选择的边缘入口、D61。本章写浏览器入口的边缘对每个请求做的事。实现是 `be-edge`：默认边缘 Traefik 上是它的插件，换别的边缘产品时是按同一套规则的旁挂进程。边缘不是组件：它用服务身份 `infra/edge` 调身份成员的 `SessionService`（[08](08-identity-authz-audit.md) 的 P8.28）。它不核验令牌、不判授权：每个组件自己核验（P8.1），绕过边缘不会让安全变弱。

| 编号 | 层级 | 规则 | 检验 |
| --- | --- | --- | --- |
| P11.1 | 必须 | 浏览器请求里的 `Authorization` 一律剥掉。带会话 Cookie（`be_session`）的请求，按 Cookie 值的摘要（小写十六进制 SHA-256）取缓存的访问令牌，注入 `Authorization: Bearer`；缓存条目在 `min(expires_at, session_until)` 前 30 秒作废。没有可用的令牌就调 `Exchange`：同一实例上同一会话同时只有一次换取在途，其余请求等它的结果。不带会话 Cookie 的请求不注入，照常转发（公开路由、外部回调） | 向量 `edge-flow`、CK-EDGE-01 |
| P11.2 | 必须 | 带会话 Cookie、方法改变状态（`POST`、`PUT`、`PATCH`、`DELETE`）、缺请求头 `BE-Request: 1` 的请求，答 `CSRF_HEADER_REQUIRED`（403），不转发。`SameSite=Lax` 的 Cookie 在跨站的顶层导航里照样带上；这条请求头保证这类导航改变不了状态 | 向量 `edge-flow`、CK-EDGE-02 |
| P11.3 | 必须 | 组件答 `TOKEN_STALE`：丢弃该会话缓存的令牌，调 `Exchange`。会话仍活着，就带新令牌把同一个请求重放一次；只重放请求体已缓存的请求（不超过 `B_replay`，起始 1 MiB；更大的请求体边转发边读，不缓存），请求体超过 `B_replay` 的不重放，答 `AUTHORIZATION_UNPROVABLE`（503，可重试）。重放的结果原样返回（成功、403、409、5xx 都是）；重放仍答 `TOKEN_STALE`，答 `SESSION_ENDED`（401）。这是边缘唯一的重试：其他失败（超时、连接中断、5xx）不重试，原样返回 | 向量 `edge-flow`、CK-EDGE-03 |
| P11.4 | 必须 | `Exchange` 答 `SESSION_ENDED`：丢弃这个会话的缓存，答浏览器 `SESSION_ENDED`（401）；前端只在这个原因上跳转登录页。身份成员不可达或答可重试的错误：答 `DEPENDENCY_UNAVAILABLE`（503，`metadata.dependency` 为 `iam`，可重试）；会话不结束 | 向量 `edge-flow`、CK-EDGE-04 |
| P11.5 | 必须 | 每个边缘实例每 `P_inv`（起始 1 秒）调一次 `Ended`，丢弃列出的会话的缓存；回答 `reset=true` 时清空全部缓存（每个会话下一次请求换取一次）。进程启动时缓存为空，第一次调用不带游标。调不通时缓存照用：结束会话都在身份成员里办理，它不可达期间的结束最迟在令牌到期时生效（D61） | CK-EDGE-05 |
| P11.6 | 必须 | 经边缘的登出请求（身份成员的登出路由）答成功之后，边缘立即丢弃这个会话的缓存，不等下一次 `Ended` | CK-EDGE-05 |
| P11.7 | 必须 | 带请求头 `BE-Polling: 1` 的请求触发的换取，`renew_idle` 为假 | CK-EDGE-01 |
| P11.8 | 必须 | 部署清单 `features`（装配工具生成，协议 20）只给有活着的会话的请求：缓存命中或换取成功；没有会话 Cookie 或会话已结束，答 `SESSION_ENDED` | CK-EDGE-06 |
| P11.9 | 必须 | Cookie、会话摘要与令牌从不进入边缘的日志、追踪与指标 | CK-EDGE-07 |
| P11.10 | 内部 | 缓存放在插件的包级变量里：Traefik 每次动态配置重载都重建中间件，包级的状态不丢；进程重启丢掉缓存，各会话下一次请求换取一次 | `be-edge` 测试 |
| P11.11 | 必须 | **组件的公网前缀**：每个组件在定义里声明一个公网路径前缀（缺省 `/api/<名字>`，名字是组件身份斜杠后的部分；例 `erp/purchase` 是 `/api/purchase`），它的每条用户面路由都在这个前缀之下（以路径段为界），SDK 的标准路由（流程内核的 P17.14、冷热转层的 P15.40）也挂在它下面；边缘按前缀路由（最长前缀）。前缀之外的用户面路由，成员启动失败（BrickKit 的健康、就绪、自描述端点不在用户面）。两个组件的前缀相同或一个是另一个的前缀段，装配工具生成边缘的路由时拒绝（随路由的生成实现）。成员在自描述里报出它的前缀。跑流程内核的组件前缀必须是缺省值：统一待办由任务的发布者推出决定的入口（P17.14），不读投影里的地址 | SDK 测试 |

## 检查编号

| 编号 | 检查 |
| --- | --- |
| CK-EDGE-01 | 同一会话的请求只在第一次与令牌快到期时换取，同时到来的未命中只换取一次；注入的令牌就是换取得到的；浏览器自带的 `Authorization` 到不了组件；轮询请求的换取不续期空闲 |
| CK-EDGE-02 | 带会话 Cookie 的 `POST` 缺 `BE-Request` 被拒且组件没有收到；带上就照常转发；不带 Cookie 的外部回调照常转发 |
| CK-EDGE-03 | 入口组件答一次 `TOKEN_STALE` 时，组件收到同一个请求两次、第二次带新令牌，浏览器得到第二次的结果；第二次仍是 `TOKEN_STALE` 时浏览器得到 `SESSION_ENDED`；请求体超过 `B_replay` 时不重放、答 503；5xx 与超时不重放 |
| CK-EDGE-04 | 会话结束后换取答 `SESSION_ENDED`；身份成员停止时，还有缓存的会话照常，没有缓存的答 503 而会话保留，身份成员恢复后照常 |
| CK-EDGE-05 | 在身份成员结束一个会话（另一个边缘实例上的登出、改密码、停用）后 `P_inv` 加一次往返内，这个边缘实例不再注入它的令牌；身份成员换纪元或游标过期时清空缓存 |
| CK-EDGE-06 | 未登录取不到 `features`，登录后取得到 |
| CK-EDGE-07 | 边缘的日志、追踪与指标里没有 Cookie、会话摘要与令牌的片段 |
