# 09 列表、搜索与投影

依据：装配项目协议 14 的“列表：游标、排序与筛选”与参数起始值；安全 07 的分页与游标、受限字段的排序与筛选；协议 02 的投影行字段、接收规则、对齐（全量重新取回）。本章先写组件自己的列表与列表内搜索，以及投影的接收规则与全量重新取回；水位来源的回声、补取与连续位置随后续任务加入。

## 列表

| 编号 | 层级 | 规则 | 检验 |
| --- | --- | --- | --- |
| P9.1 | 必须 | 列表只用游标分页（keyset），不用偏移量。排序键之后总是追加记录身份（升序）作为最后的比较键；可排序的字段由资源声明，且不为空 | 向量 `list-pages` |
| P9.2 | 必须 | 页大小缺省 50、上限 200；0 或超过上限答 `REQUEST_INVALID` | 向量 `list-pages` |
| P9.3 | 必须 | 游标是不透明的字符串，内容为（版本、最后一行的排序键值与身份、筛选摘要、计划摘要）的规范 JSON 的 base64url。筛选摘要覆盖筛选、`q` 与排序；计划摘要覆盖该主体在该资源类型上的规范化段集合与资源定义的摘要。每页按当前授权重新编译：筛选摘要不同答 `CURSOR_INVALID`，计划摘要不同答 `QUERY_PLAN_CHANGED`（重新查询），不沿旧游标继续 | CK-LS-01 |
| P9.4 | 必须 | 筛选、排序与搜索只用资源声明为可用的字段；值全部作参数，列名只来自声明。按受限字段筛选或排序，要求调用者在该操作的每个可见段上都能读该字段，否则答 `FIELD_NOT_QUERYABLE`（安全 07 的充分条件的简化：每段都含该字段） | CK-LS-02 |
| P9.5 | 必须 | 列表的完整条件 = 授权谓词（[08](08-identity-authz-audit.md) 的 P8.17）AND 请求的筛选 AND 搜索 AND 游标位置，在同一条 SQL 中；先授权再排序分页 | CK-LS-01 |

## 列表内搜索

| 编号 | 层级 | 规则 | 检验 |
| --- | --- | --- | --- |
| P9.6 | 必须 | 可搜索的字段写进规范化的搜索列（版本 1）：每个字段值折叠（NFKC、小写、去掉 Unicode 类别 Cc 与 Cf 的字符），再加全拼与首字母；拼音来自本仓库 `data/pinyin.tsv`（每个汉字的首选读音、无声调；三种语言用同一张表，多音字因此一致）。各段用 U+001F 连接。搜索列随行写入并记规范化版本，版本升高时由工作项回填 | 向量 `search` |
| P9.7 | 必须 | 查询 `q` 同样折叠并去掉首尾空白，为空等于没有条件；匹配 = `q` 是搜索列某一段的子串（不跨段），`%`、`_` 按字面。`q` 计入筛选摘要 | 向量 `search` |
| P9.8 | 必须 | 搜索列按字段的读取许可分开：一列只由同一读取许可的字段组成。`q` 只匹配调用者对组成字段全部可读的列；请求显式指定了不可读的列时答 `FIELD_NOT_QUERYABLE` | CK-LS-02 |
| P9.9 | 应当 | 搜索列的索引按库中可用的扩展选择（`pg_trgm` 或 `pg_bigm`，迁移中以属主身份建立）；缺扩展只会变慢，结果相同 | — |

已知限制（与装配项目协议 14 相同）：多音字只取一种读音（例如“银行”的首字母是 `yx`，需要时加助记码）；没有容错、同义词与相关度；繁简不折叠。

## 投影

| 编号 | 层级 | 规则 | 检验 |
| --- | --- | --- | --- |
| P9.10 | 必须 | 投影行带：来源、记录身份、版本、状态（`complete`、`incomplete`、`tombstone`）、需要的版本（`incomplete` 时）、所属的实现实例与纪元、内容；表在消费者自己的 schema（本仓库 `migrations/0005_projection.up.sql`） | CK-PJ-01 |
| P9.11 | 必须 | 接收按装配项目协议 02 的接收规则与状态迁移表。先把输入与该来源**已采用**的实现实例与纪元比较（已对齐过时）：别的实现实例的输入不应用（退役的忽略，待采用的由对齐采用）；更小纪元的忽略；更大纪元的不应用，先对齐再说。之后：本地行属于旧实现实例或旧纪元时由完整状态与删除直接覆盖；其余按状态表：完整状态按版本覆盖；部分字段把行置为 `incomplete` 并排入取回；删除写墓碑；墓碑不被同版本或更旧的数据复活；读取结果“已清理”从任一状态写“版本 0”的墓碑。同一条记录的输入串行处理（行还不存在时也是），并发的旧输入不能不经比较就覆盖新输入 | 向量 `projection-apply`、CK-PJ-03 |
| P9.12 | 必须 | 全量重新取回（对齐）：推进对齐代次，分页读取来源的全部记录写入（直接覆盖，记已采用的实现实例与纪元）；本地有而快照没有的行，按身份向来源批量读取：墓碑写墓碑、仍存在的覆盖、已清理的写“版本 0”的墓碑。对齐进行中按 P9.11 接收的行记为“对齐期间写入”：快照只以更新的版本覆盖它，按身份的读取不碰它（交给流）。带旧对齐代次的读取结果一律丢弃。完成后投影与来源一致 | CK-PJ-02 |

## 检查编号

| 编号 | 检查 |
| --- | --- |
| CK-LS-01 | 翻页期间插入与删除不重复不遗漏（游标语义内）；筛选改变或授权改变时游标失效 |
| CK-LS-02 | 不可读的受限字段不能用于筛选、排序或搜索 |
| CK-PJ-01 | 投影表的形状 |
| CK-PJ-02 | 对齐之后投影的每一行与来源一致；对齐期间的旧读取不会复活已删除的行 |
| CK-PJ-03 | 对齐之后旧实现实例与其他纪元的迟到输入不改动投影；同一条新记录的删除与更旧的完整状态并发到达时，墓碑保留；补全遇到“已清理”写“版本 0”的墓碑 |
