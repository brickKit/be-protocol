# 07 后台工作项

依据：装配项目协议 01（后台工作与崩溃恢复：状态、字段、状态迁移表、认领与接管、副作用种类、cron 时间槽、singleton、清理资格、参数起始值）；协议 14 的库内计数与纪元。状态迁移的完整表在协议 01，本章写组件与 SDK 必须遵守的形状与可检验的规则。

## 表与身份

| 编号 | 层级 | 规则 | 检验 |
| --- | --- | --- | --- |
| P7.1 | 必须 | 工作项在组件自己 schema 的 `be_work_item` 表（本仓库 `migrations/0003_work.up.sql`），cron 的物化水位在 `be_cron_watermark`；外壳的成员互不共享 | CK-DB-05 |
| P7.2 | 必须 | 身份：queue 为 UUIDv7；cron 为 `<作业名>@<时间槽身份>`；singleton 为作业名。`operation_id`：queue 为 `<身份>:<作业名>`，在排入时写；cron 在物化时写不复用的身份；singleton 每一段在提交上一段进度的同一事务中生成。认领、接管与重新排队沿用 | CK-WK-01 |
| P7.3 | 必须 | queue 工作项与业务写入在同一个本地事务中排入；事务回滚则不排入 | CK-WK-01 |
| P7.4 | 必须 | 作业声明副作用种类：`local`、`idempotent_external`、`non_idempotent_external`、`emit_only`（归入 `local`）；不在运行时推断 | — |

## 认领、租约与代次

| 编号 | 层级 | 规则 | 检验 |
| --- | --- | --- | --- |
| P7.5 | 必须 | 认领是一条原子的条件更新（协议 01 的认领语句）：`pending`，或 `retry_wait` 且 `run_at <= now()`，或 `running` 且 `lease_until <= now()`（接管）；代次加一、尝试次数加一，写持有者、`lease_until = now() + 租约`、认领纪元 = `be_current_db_epoch()`。时间一律用数据库时钟 | CK-WK-02 |
| P7.6 | 必须 | 每次提交与续租的条件都核对：代次与认领纪元等于**自己认领时得到的**值，且认领纪元等于当前的库纪元；不符时影响零行，持有者立即取消本次执行 | CK-WK-03 |
| P7.7 | 必须 | 租约起始 30 秒，按三分之一续租 | CK-WK-03 |
| P7.8 | 必须 | 停止时取消正在运行的处理器；处理器结束后释放自己持有的租约（`lease_until = now()`，核对代次），撤回这次认领的尝试计数，使其他副本立即可以接管；释放不改变 `outcome_unknown` | CK-WK-04 |
| P7.9 | 必须 | 两个副本同时认领同一工作项时只有一个成功；同一定时槽在两个副本同时物化与认领时只执行一次 | CK-WK-05 |
| P7.21 | 应当 | queue 工作项排入的业务事务提交后，同一进程里这个成员的工作者立即认领，不等下一次轮询；轮询只兜底别的副本排入的项、重试与接管。只在提交之后唤醒：事务内唤醒时新行还不可见。一次提交排入几项就唤醒几个工作者，至多全部工作者；被唤醒的工作者与轮询一样认领任何到期的项。没有唤醒时，每一项都要等半个轮询间隔（500 毫秒的轮询下实测“事件到达 → 后台调用完成”p50 约 250 毫秒、p99 约 500 毫秒），“事件 → 工作项 → 调用”这样的链路每一跳都白等 | SDK 测试 |
| P7.22 | 应当 | 领取的代价不随积压增长：先按租约到期时刻取一条租约已过期的项，没有时再按 `run_at` 取一条到期项，各走一个按自己的顺序排好的部分索引（本仓库 `migrations/0008_work_claim_order.up.sql`），在同一条语句里完成；不跨两个部分索引做 `OR` 再排序。那种写法每次领取都取出全部积压再排序：2 万条积压时一次 3–8 ms，改后 0.1–0.2 ms。先取过期的，被接管的项不会因为一直有新的到期项而饿死 | SDK 测试 |

## 只发生一次

| 编号 | 层级 | 规则 | 检验 |
| --- | --- | --- | --- |
| P7.10 | 必须 | `local`：效果与“标记完成（核对代次）”在同一个本地事务中提交 | CK-WK-06 |
| P7.11 | 必须 | `idempotent_external`：所有尝试携带同一个 `operation_id`（一次运行内的多个调用用 `<operation_id>:<子键>`，子键按语义取）；接管后先按键查询对方，再决定是否重发 | CK-WK-06 |
| P7.12 | 必须 | `non_idempotent_external`：发出前在一个本地事务中把 `outcome_unknown` 置真（核对代次），事务确认后才发出；出错时只有确认“未生效”才按可重试处理并清除；不能确认的转 `paused`（`outcome_unknown`）；任何一次认领发现它仍为真，转 `paused`，不重发 | CK-WK-07 |
| P7.13 | 必须 | 失败：可重试且未到上限 → `retry_wait`，`run_at` 按退避（1 秒起加倍，上限 5 分钟）；用完或不可重试 → `dead`，在同一个本地事务中调用作业的死信处理（只写本地数据与发件表）；业务等待 → `retry_wait` 且撤回尝试计数，超过声明的等待上限按不可重试 | CK-WK-08 |
| P7.14 | 必须 | `dead`、`paused` 不自动重试、不自动清理；重新排队与标记已解决按协议 01 的守卫，由有权限的操作者执行并写审计（审计随审计客户端接入） | CK-WK-08 |

## 定时与长任务

| 编号 | 层级 | 规则 | 检验 |
| --- | --- | --- | --- |
| P7.15 | 必须 | cron 计划写成 5 字段表达式（分、时、日、月、星期；支持 `*`、列表、区间、步长；星期 0 与 7 都是星期日）加一个 IANA 时区（法人的业务时区或作业声明的时区）。时间槽身份 = 本地日期与本地时刻 `YYYY-MM-DDTHH:MM`。本地时刻不存在（夏令时开始）时在跳变后的第一个有效时刻执行，身份不变；本地时刻出现两次（夏令时结束）时只在第一次执行 | 向量 `cron-slots` |
| P7.16 | 必须 | 调度器锁住作业的物化水位行，只物化水位之后到期的槽，与水位一起提交；首次见到的作业以当前时刻为水位，不补历史。补跑策略 `latest`（缺省，只补最近一个）、`all`（最多 24 个，超出的物化为 `paused`（`backlog_exceeded`））、`none` | 向量 `cron-slots`、CK-WK-05 |
| P7.17 | 必须 | singleton 以作业名为身份，持租约运行；长任务分段提交进度，每段核对代次并为下一段生成 `operation_id`；一次运行完成后按声明的间隔重新进入 `pending` | CK-WK-09 |
| P7.18 | 应当 | `every`：每个副本按自己的计时器运行，处理的业务行由业务表逐行原子认领（`FOR UPDATE SKIP LOCKED`）；不进入工作项表 | — |

## 清理与观测

| 编号 | 层级 | 规则 | 检验 |
| --- | --- | --- | --- |
| P7.19 | 必须 | `done`、`resolved` 的 queue 工作项保留 7 天，cron 工作项在槽早于物化水位且超过 30 天后可删，由 SDK 自带的 singleton 作业 `be.work.cleanup`（每小时）删除；`dead`、`paused` 不自动删除。长期去重落在业务表的唯一约束上，不依赖工作项表 | CK-WK-10 |
| P7.20 | 应当 | 每个作业提供运行次数与结果、耗时、最近成功的时刻、队列深度、最老 `pending` 的等待时长、`dead` 与 `paused` 的数量。进入 `dead`、`paused` 的摘要事件随死信监控组件加入 | — |

## 检查编号

| 编号 | 检查 |
| --- | --- |
| CK-WK-01 | 业务事务回滚时没有工作项；`operation_id` 在接管与重新排队后不变 |
| CK-WK-02 | 租约到期的工作项被另一个工作者以原身份接管，代次加一 |
| CK-WK-03 | 被接管的旧持有者续租与提交都影响零行，并取消执行；推进部署恢复代次后旧认领同样失效 |
| CK-WK-04 | 停止时释放租约，另一个副本不等租约到期就接手，尝试计数不增加 |
| CK-WK-05 | 两个副本同时物化并认领同一定时槽，只执行一次（RT08） |
| CK-WK-06 | `local` 作业在效果与完成标记之间崩溃，接管后效果只有一次 |
| CK-WK-07 | 非幂等调用发出后崩溃，接管者转 `paused`，不重发 |
| CK-WK-08 | 可重试错误按退避重试，用完进 `dead` 并调用死信处理；`dead` 不自动重试 |
| CK-WK-09 | singleton 换持有者后从已提交的进度继续，沿用这一段的 `operation_id` |
| CK-WK-10 | 清理不删未到保留期的行，也不删 `dead`、`paused`；清理后同一槽不会重新物化 |
